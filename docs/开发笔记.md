# 错题集 · 开发笔记

> 这个项目从「一个能用的网页」长成「一个能装的 APP」，中间踩过的坑都记在这里。
> 想改代码、想过一遍架构、想接手继续做，读完这份就够开工了。

## 这是什么

一个**本地优先的错题本**：拍照/粘贴 → 题目入库 → 按遗忘曲线复习 → 斩题/统计/出卷。
纯前端（单文件 `index.html` + 本地静态服务），外面套了一个 Android WebView 壳。


重点看：**拍照按钮是不是真的开相机了**（这一版才修）、相册选图、返回键、识图能不能连上
（现在走原生通道，不需要本机服务和代理）。

### 2. 原生 HTTP 桥（已实现，改的时候注意）

网页版的 AI 请求要走 `/proxy`，因为浏览器有跨域限制；**APP 里不该继续依赖代理**。
现在的做法：

```
JS 侧：hasNative() → nativePost(url, payload)
Java 侧：@JavascriptInterface 的 NativeHTTP.post(url, headersJson, body, callbackId)
        发完请求回调 window.__nativeHTTPDone(id, raw)
```

两个容易改坏的地方：

- **别退回同步接口**。识图经常要几十秒，同步返回会把 JS 线程整个卡住，转圈的动画也停。
  所以 Java 侧开线程发请求，再 `post()` 回主线程用 `evaluateJavascript` 回调。
- **返回值和 fetch 的 Response 保持同形状**（`ok` / `status` / `text()`），
  这样 `aiChat()` 后面的代码不用分叉。

### 3. 硬编码的私有地址（已去掉）

`web/index.html` 里 `REMOTE_PROXY` 现在是空串。别把它改回某个人的 Worker 地址——
开源的版本不该把用户固定引流到别人的服务上。需要跨站代理的用户自己在「设置」里填。

### 4. 拍照按钮（已修，原理值得记一下）

网页里写的是 `<input type="file" accept="image/*" capture="environment">`，
但 **WebView 会忽略 `capture`**：`FileChooserParams.createIntent()` 永远返回相册的
`ACTION_GET_CONTENT`。所以「拍照」和「相册」两个按钮表现一模一样。

修法在 `onShowFileChooser`：先看 `params.isCaptureEnabled()`，为 true 就自己发
`MediaStore.ACTION_IMAGE_CAPTURE`，用 `FileProvider` 给一个 `cache/camera/` 下的可写地址，
拍完在 `onActivityResult` 里把那个 content URI 交回给 WebView；失败就退回相册。
配套改动：`AndroidManifest.xml` 里的 `<queries>` + `<provider>`、`res/xml/file_paths.xml`、
`build.gradle.kts` 里的 `androidx.core`。

## 已知的坑（省你时间）

1. **Windows 中文用户名**：AGP 会直接拒绝非 ASCII 项目路径，且 Java 写不进 `~/.android`。
   完整解法见 `docs/本地构建.md`（用 junction 躲开中文路径 + 重定向 user.home/tmpdir）
2. **WebView 的 file chooser**：各家 ROM 差异大，`onShowFileChooser` 已经实现在 `MainActivity`，
   但部分机型需要额外加 `READ_MEDIA_IMAGES` 权限或改用 `ACTION_GET_CONTENT`；
   `capture` 属性在 WebView 里默认无效，相机要自己发 Intent（见上面第 4 条）
3. **IndexedDB 要求安全来源**：壳里用的是 `https://appassets.androidplatform.net`，
   千万别改成 `file://` 加载，否则数据库直接不可用
4. **Service Worker 在 WebView 里可用**，但首次加载才注册；调试时建议先禁用 SW 再改代码
5. 网页里 `checkNewVersion()` 会去请求 `version.json`，APP 里可以留着（本地资源，无害）
6. **WebView 默认不支持 `confirm()` / `alert()`**
   这是最容易踩的坑：没实现 `onJsConfirm` 时，`window.confirm()` 直接返回 `false`，
   网页里所有「确定要删除吗」都会变成**静默取消**（表现为点了没反应、数据没变）。
   壳里已经实现了 `onJsAlert` / `onJsConfirm`（`MainActivity.java`），
   如果你改动壳代码，别把这两个方法删了。
