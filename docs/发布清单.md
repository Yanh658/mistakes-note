# 发布清单

> 从「本地能跑」到「GitHub 上有人能下载」，一共就这些事。
> 一次性配置做完之后，每次发版只走最后一节。

## 一、先确认仓库里没有私货

发布前跑一遍（在仓库根目录）：

```bash
grep -rn -E "workers\.dev|@qq\.com|@gmail\.com|sk-[A-Za-z0-9]{20,}" \
  --include=*.md --include=*.js --include=*.html --include=*.toml . | grep -v node_modules
```

应该只剩「占位符/示例」这类命中。特别注意：

- ❌ `web/部署说明.md` 里别留自己的 Cloudflare 账号、子域名
- ❌ 别把 `android/keystore.jks` / `keystore.properties` 提交上去（`.gitignore` 已挡）
- ❌ 别把 `dist/`、`android/app/build/` 提交上去（`.gitignore` 已挡）
- ❌ 别把带个人路径的构建笔记原样贴进来（用 `<你的用户名>` 代替）

`android/local.properties` 里有你本机的 SDK 路径，同样不该提交。

## 二、生成签名密钥（只做一次）

```bash
keytool -genkeypair -v \
  -keystore cuoti-release.jks \
  -alias cuoti \
  -keyalg RSA -keysize 2048 \
  -validity 10000
```

- 放在**仓库外面**，或者至少确认 `git status` 里看不到它
- 密码、别名抄到密码管理器里。**丢了就再也发不了同一个 App 的更新**
- 有了这个文件，以后所有版本都必须用同一个签名，否则用户装不上（签名不一致）

## 三、配置 GitHub Secrets

仓库 → Settings → Secrets and variables → Actions → New repository secret，四个：

| Name | 值 |
|---|---|
| `KEYSTORE_BASE64` | 整个 jks 的 base64 文本 |
| `KEYSTORE_PASSWORD` | keystore 密码 |
| `KEY_ALIAS` | `cuoti` |
| `KEY_PASSWORD` | key 密码（一般同上） |

生成 base64：

```powershell
# Windows PowerShell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("cuoti-release.jks")) | Set-Clipboard
```

```bash
# macOS / Linux
base64 -w0 cuoti-release.jks | clip   # 或 pbcopy
```

⚠️ base64 文本通常有几千字符，别用记事本换行，直接粘贴原样。

## 四、首次推送

```bash
git init
git add .
git commit -m "feat: 错题集 v1.2.0"
git branch -M main
git remote add origin git@github.com:YOURNAME/cuoti.git
git push -u origin main
```

推之前顺手改两处占位符：

- `README.md` 里的 `YOURNAME/cuoti`（徽章和下载链接，共 3 处）
- 如果你想用别的包名，改 `android/app/build.gradle.kts` 里的 `applicationId`
  （改了之后已装的旧包会被当成另一个 App，数据不通）

## 五、发版

版本号有三处要一起改（前端自检靠它提示用户刷新）：

```bash
# web/index.html
const APP_VER = 'v29';
# web/version.json
{"v":"v29"}
# web/sw.js
const VER = 'cuoti-v29';
```

Android 侧改 `android/app/build.gradle.kts` 的 `versionCode` / `versionName`，然后：

```bash
python3 scripts/sync_assets.py          # 同步到 assets
git add -A && git commit -m "chore: v1.3.0"
git tag v1.3.0
git push origin main --tags
```

打上 `v*` 标签后，Actions 会自动：构建 release 包 → 用 Secrets 里的密钥签名 →
把 `cuoti-v1.3.0.apk` 传到 Releases 页面。

想先在本地验证：

```bash
cd android
./gradlew assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

本地构建要签名的话，在 `android/keystore.properties` 里写：

```properties
storeFile=../cuoti-release.jks
storePassword=你的密码
keyAlias=cuoti
keyPassword=你的密码
```

（这个文件已被 `.gitignore` 忽略。没有它也能构建，只是出的是未签名的 release 包。）

## 六、发完检查

1. Releases 页面有 APK，大小对得上（约 2.8 MB）
2. `apksigner verify --print-certs 下载的.apk` 显示的是你的证书，不是 `Android Debug`
3. 手机上装得进去（如果之前装的是 debug 包，要先卸载——签名不同）
4. 第一次打开能建题库，拍照能调起相机

## 常见问题

**CI 报 `缺少 Secrets.KEYSTORE_BASE64`**
Secrets 没配，或者名字拼错（大小写敏感）。

**CI 报 `assets 和 web 不一致`**
改了 `web/` 但忘了 `python3 scripts/sync_assets.py`。

**装 APK 时报「应用未安装」/「签名不一致」**
手机上还装着 debug 版或别人签的版本，先卸载。

**Release 里想改说明**
`softprops/action-gh-release` 会自动生成 `generate_release_notes`，
之后在 GitHub 上直接编辑那条 Release 的正文即可。
